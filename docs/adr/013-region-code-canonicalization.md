# 013. 행정구역 코드 표준화 — 내부는 구코드, 경계에서 변환

- **상태**: Accepted
- **날짜**: 2026-08-02

## 맥락

시군구 코드는 이 시스템에서 세 역할을 동시에 맡는다.

1. **식별자** — PNU(apartments PK) 앞 5자리
2. **조인 키** — 범죄·관리비·안전지수 등 시군구 통계 테이블 18개 컬럼
3. **외부 API 파라미터** — 국토부 거래 수집 순회, 건축물대장 조회

행정구역 개편으로 외부 세계가 신코드를 쓰기 시작했다 (2026-08 실측):

- Kakao b_code 가 광주 북구를 `29170` 이 아닌 `12300`(전남광주통합특별시)으로 반환. 전남 시군 전체가 `12xxx` 로 재부여됨
- **신코드는 기존 API 에서 죽은 코드다** — 건축물대장에 `12300` 조회 시 응답 없음, `29170` 은 정상
- 법정동 코드(6~10자리)는 개편 전후 보존됨 (오치동 `11500` 등)
- 신 명칭 주소 문자열("전남광주통합특별시", 화성 동탄구 등)이 이미 DB 에 400건 이상 유입

경계 없이 신코드가 유입되면 같은 단지가 두 PNU 로 갈라진다. 실제로 SGG_MISMATCH 808건이 이 문제로 차단됐고(PR #210 에서 거래 원본 조합으로 회수), 부천/화성 통합코드, 좌표 파이프라인 오판 등 같은 뿌리의 사고를 세 차례 겪었다. 그때마다 지점별 국소 우회로 대응했고 신·구 대응이 어디에도 기록되지 않았다.

## 결정

1. **내부 표준 코드는 구코드(현행 레지스트리)로 유지한다.** PNU 는 구코드 기반 불변 식별자다.
2. **외부에서 들어오는 코드는 경계에서 정규화한다.** 별칭 레지스트리(`common_code` group `sigungu_alias`: 신코드 → 표준코드)와 순수 변환 모듈(`batch/region_codes.py`)을 둔다.
3. **별칭은 실측으로만 만든다.** 시군구마다 실제 단지 지번을 지오코딩해 응답 b_code 를 그 단지 PNU 와 필지 단위(법정동·본번·부번)로 대조하고, 일치할 때만 대응으로 인정한다 (`scripts/seed_sigungu_aliases.py`).
4. **재편(구 경계 변경) 지역은 법정동 단위로 푼다.** 재편에는 두 유형이 있다 (2026-08 실측).
   - 법정동 보존형(광주·전남): 5자리 별칭, 시군구만 치환
   - **법정동 재부여형(인천 중·동·서구)**: 동들이 합쳐지며 법정동 코드까지 재배열된다(중구 답동 `2811012500` → `2812513200`). 10자리→10자리 별칭으로 앞 10자리를 통째로 바꾼다. 이 유형에서 5자리 치환은 엉뚱한 동의 PNU 를 만들므로, 재부여 매핑에 등장하는 신코드는 5자리 별칭을 금지한다(인천 동구가 병합 코드 28125 로 개명 판정됐다가 강등된 사례). 미커버 법정동은 변환하지 않는다 — SGG 가드 → 거래 기반 재조합 경로로 안전하게 빠진다.

## 근거

- **전면 신코드 이관의 비용**: PNU PK 재작성(단지 4.2만 + 매핑 4.5만 + 부속 100만 행), 아직 구코드만 받는 외부 API(건축물대장·국토부 거래), 시군구 통계 시계열 단절. 반면 경계 변환은 유입 지점 수 곳만 고치면 된다.
- **법정동 보존이 변환을 가능하게 한다**: 앞 5자리만 치환하면 PNU 가 이어진다.
- **추측 매핑의 위험**: 같은 구 이름("동구·남구·북구")이 전국에 중복되어 명칭 기반 대응은 오판한다(실제로 겪음). 필지 대조만이 안전하다.
- 외부가 완전히 신코드로 전환되어 전면 이관이 불가피해지면, **별칭 테이블이 그대로 마이그레이션 맵이 된다.**

## 결과

- 2026-08 프로브(개선 후): 시군구 258개 중 변화 없음 224, 개명 24+α, 재부여형 검출. 최종 별칭 67건 = 5자리 27(광주 5 + 전남 22) + **10자리 40(인천 중·동·서구 전수 필지대조)**. 인천 중구 검증 실패의 원인은 법정동 재부여였고, 신안 46910 은 법정동 보존 확인 후 행정단위 근거로 12870 대응을 등록했다(단지 1곳의 PNU-지번 불일치로 필지 완전검증 불가)
- 시도명 별칭은 보류 — `common_code sigungu` 의 `extra` 가 시도명이 아니라 도시명인 행이 섞여 있어("청주", "창원", "경기 화성시") 자동 수집이 오류 쌍을 만든다. 시도 레지스트리 정비가 선행돼야 한다.
- 후속(Phase 2): Kakao b_code 를 받는 지점(`enrich_apartments`, `register_missing_apartments`, `fix_coord_drift`)에 `normalize_sigungu`/`normalize_pnu` 적용
- 후속(Phase 3): 배치 감사(#211)에 미등록 코드 유입 경보 추가 — `is_known_sigungu` 로 다음 개편을 사고 전에 감지
