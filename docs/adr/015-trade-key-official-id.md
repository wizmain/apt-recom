# 015. 거래 키를 국토부 단지 고유번호(aptSeq)로 전환

- **상태**: Proposed
- **날짜**: 2026-10-13
- **설계서**: `docs/superpowers/specs/2026-10-13-trade-key-official-id-design.md`

## 맥락

`trade_history`/`rent_history` 의 거래 키 `apt_seq` 는 `"{시군구}_{단지명}"` 으로 만든다
(`batch/trade/load_trades.py`). 같은 시군구에 이름이 같은 단지가 있으면 거래가 한 키로 합쳐지고,
그 키는 `trade_apt_mapping` 에서 PNU 하나에만 매핑된다.

2026-10-13 동작구 value 카드에서 `11590_대림아파트` 가 대방대림(대방동 501, 1993, 600건)과
상도1동대림(상도동 411, 1995, 130건)을 합치고 있어, 카드의 "대방대림"이 상도1동대림 거래로 계산된 채
게시됐다(정정 재게시, PR #314). 로컬 실측으로 국토부 aptSeq 2개 이상을 품은 기존 키가 498개,
법정동·준공연도가 모두 2개 이상인 키가 432개(거래 약 10.4만 건)다.

이름 기반 키라 같은 문제가 재발한다. 이상치 규칙(PR #311)은 혼입을 고치지 못하고 진짜 거래를 버릴 수 있다.

## 결정

1. 거래 키 `apt_seq` 는 국토부 aptSeq 를 쓴다. aptSeq 가 없을 때만 기존 `"{시군구}_{단지명}"` 을 쓴다.
   키는 불투명 문자열이며 시군구는 `sgg_cd` 칼럼에서 읽는다.
2. 새 키의 매핑은 혼입이 증명된 키만 귀속을 바꾸고 나머지는 기존 매핑을 상속한다
   (상속 → 주소 PNU → 법정동 내 이름 매칭 → 미매핑 보고). fallback 매핑은 두지 않는다.
3. 과거 행은 기존 키 안에서 학습한 서명(매매: 준공연도·면적, 전월세: 면적)이 **유일하게** 가리킬 때만
   aptSeq 키로 바꾸고, 혼입 키의 잔여분만 API 로 재수집한다. 원래 키는 `legacy_apt_seq` 에 보존한다.

## 결과

- 신규 거래는 동명 단지와 섞이지 않는다. 혼입 감시 목록 같은 유지 부담이 없다.
- 이름 변형(같은 단지의 다른 표기)이 하나의 키로 모인다.
- 한 단지에 기존 키와 aptSeq 키가 공존하는 기간이 있으나 같은 PNU 로 매핑돼 소비자는 영향이 없다.
- 운영 반영에 대량 UPDATE 가 필요하다(구 단위·롤백 가능).
- aptSeq 를 관측하지 못한 오래된 키의 숨은 혼입은 남는다.

## 기각한 대안

- 혼입 키만 `{sgg}_{name}({jibun})` 로 분할 — 두 키 체계 공존, 새 충돌마다 분할 목록을 추가해야 한다.
- 매핑에 준공연도 구분 칼럼 추가 — 소비자 조인 전면 수정, 전월세에 준공연도가 없다.
