# 017. 상속 매핑에도 물리 판정을 적용하고 이름 불일치를 보강 신호로 쓴다 (ADR-015 보완)

- **상태**: Proposed
- **날짜**: 2026-11-16
- **보완 대상**: [ADR-015](015-trade-key-official-id.md) 결정 2 (새 키 매핑의 상속 우선)
- **분석 산출물**: `reports/trade_mix_detect/` (로컬 전용, gitignore)

## 맥락

2026-11-16 로컬 DB 오프라인 분석(코드·DB 변경 없음)에서, 한 단지(pnu)에 이름이 다른 단지의 거래 키가
붙어 있고 그 키의 건축년도가 단지 준공연도와 2년 이상 어긋나는 경우가 **615키 / 293단지 / 2022년 이후
매매 17,308건** 나왔다(서울 1단지, 수도권 104단지 — 인천·부산·대구에 집중). 예: 인천
두산위브더제니스센트럴여의에 약 50개 단지 거래, 부산 화명대림타운에 코오롱하늘채1·2차 거래 378건.

경로는 세 단계다.

1. **발생** — 옛 이름 키 매핑이 이름 매칭으로 만들어졌다(상속 원본 410키 중 `auto_create` 234,
   `exact_name` 126, `trade_create` 34). ADR-015 가 신뢰할 수 없다고 걷어낸 그 매칭이다.
2. **전파** — 새 고유번호 키는 이름 키의 PNU 를 상속하고(`decide_mapping` 1순위), 상속은 물리
   게이트(F2, `mapping_gate.gate_keys`)에서 면제된다. 615키 중 410키(67%)가 `api_inherit_legacy` 다.
3. **미검출** — 기존 감사(`audit_mappings.find_violations`)는 615키 중 317키만 위반으로 확정한다.
   나머지 298키는 준공연도 불일치(`timeline_violation`) 신호가 켜지지만 약한 신호 단독이라
   `mismatch_confirmed`(강한 신호 또는 2개 이상)를 넘지 못한다. 59·84㎡ 표준 주택형이라 면적이 우연히
   맞거나, 단지에 `apt_area_type` 이 없다(미검출 키의 19%). 이름 불일치(`name_consistent`)는 단독 근거
   금지 원칙 때문에 신호로 세지 않는다.

또한 현행 감사가 이미 확정하는 위반 2,438키가 정리되지 않은 채 남아 있다(2025년 이후 매매가 있는 키
1,243개, 해당 매매 22,884건). 감사 모듈은 원칙상 "판정만 하고 고치지 않는다"(사람이
`scripts/rematch_bad_mappings.py` 로 교정)인데, 그 교정이 2026-08 이후 다시 돌지 않았다.

가격 분포 군집(2-means·혼합모델 BIC, 시군구·반기·면적대 보정)으로도 탐지를 시도했으나 판별력이 없었다
— 정상 단지 분리도 중앙값 3.15, 미교정 혼입 사례 3.08. 단지 안 층·향 분산이 혼입 차이를 가린다.

## 결정

1. **판정 규칙 보강** (`batch/trade/mapping_checks.py`) — 이름 불일치는 계속 단독 근거로 쓰지 않는다.
   단, **타임라인 신호와 함께 켜질 때** 두 번째 신호로 센다(`mismatch_confirmed` 의 "2개 이상"에 포함).
   감사·게이트·`rematch_bad_mappings` 가 같은 함수를 쓰므로 세 곳에 동시에 적용된다.
2. **재건축 선행 단지는 위반이 아니다** — 키의 거래 건축년도가 단지 준공연도보다 이르고 키의 **마지막
   거래가 준공연도 이전**이면(철거된 옛 단지의 거래가 같은 부지의 새 단지 PNU 에 붙은 경우: 개포주공1단지
   → 디에이치퍼스티어아이파크) 별도 분류(`predecessor`)로 두고 위반으로 확정하지 않는다. 다른 단지 혼입이
   아니라 같은 부지의 이력이며, 최근 기간 창을 쓰는 가격 계산에는 자연히 들어오지 않는다.
3. **상속에도 게이트를 적용한다** (`trade_key_mapping` / `mapping_gate`) — 상속 판정도 넣은 직후 같은
   물리 판정을 거치고, 확정 위반이면 지워 미매핑으로 둔다(ADR-015 의 fallback 금지 원칙 그대로).
   **예외**: 상속 원본 이름 키의 `match_method` 가 `manual_fix` 이면 면제한다 — ADR-015 가 상속을 둔
   이유(사람의 교정 보존)를 지킨다. 분석 대상 혼입 키 중 `manual_fix` 출처는 0건이었다.
4. **기존 위반 정리는 기존 도구로 한다** — 새 정리 스크립트를 만들지 않는다.
   `scripts/rematch_bad_mappings.py` 를 보강된 판정으로 돌려 REMATCH(검증 통과한 대체 단지)만 반영한다.
   NO_TARGET(대체 단지 없음)은 이 도구가 지금 건드리지 않는데, 이번에 **매핑 해제 옵션**(`--unmap-no-target`,
   해제 행은 백업 테이블에 보존)을 추가한다. 해제된 키는 정기 배치의 단지 등록 경로가 다시 판정한다.
5. **순서** — 로컬 리허설 → 표본 검수 → Railway(사용자 실행) → `apt_price_score` 재계산.
   CLAUDE.md 의 production DB 직접 접속 금지 정책에 따라 Railway 반영 명령은 사용자가 실행한다.

## 검증 계획 (구현 전·후)

- **보강 규칙의 영향(사전 측정, 로컬 전체 매핑 54,429행)**: 추가 확정 583키 = 재건축 선행 80 + 혼입 503
  (2025년 이후 매매가 있는 키 387, 해당 매매 1,713건). 추가분의 `match_method` 는 `auto_create` 237,
  `api_inherit_legacy` 211, `exact_name` 81, `jibun` 27 등.
- **표본 정밀도 검수**: 추가 확정분과 현행 확정분에서 각 50키를 무작위로 뽑아 거래명·법정동·지번·건축년도로
  사람이 판정한다. 오탐률이 10%를 넘으면 규칙을 조정한 뒤 다시 측정한다(구현 진행 조건).
- **고정 대조군**: 같은 단지 별칭은 걸리지 않아야 한다 — 월계시영고층 ← 미륭·삼호3, 관악드림타운 ←
  관악드림(삼성), 목동트라팰리스 ← 트라팰리스이스턴에비뉴(모두 건축년도 일치). 혼입은 걸려야 한다 —
  화명대림타운 ← 코오롱하늘채1·2차, 봉담한신더휴에듀파크 ← 봉담아이파크·봉담센트럴푸르지오.
  재건축은 선행으로 분류돼야 한다 — 개포주공1단지, 진주 → 잠실래미안아이파크.
- **단위 테스트**: `scripts/tests` 에 판정 함수 테스트(이름+타임라인 확정, 이름 단독 불확정, 선행 분류,
  `manual_fix` 상속 면제)를 추가한다(DB 불요, CI 실행).

각 50키 무작위(seed 1116, 재건축 선행 제외), 거래명·지번·건축년도·거래 기간으로 판정.

| 보강 규칙 추가분 | 40 | 10 | 0 |

오탐은 0/50·2/50(4%)** 로 진행 조건(10%)을 통과했다. 계보 의심까지 오탐으로 치면 20%·16%다.

## 로컬 리허설 (2026-11-16)

`rematch_bad_mappings --target local` 리포트: OK 51,528 · REMATCH 284 · SAME 439 · REJECTED 302 ·
NO_TARGET 1,876(매매 7.3만, 단지 720, 서울 167). NO_TARGET 중 새 규칙(타임라인+이름)으로만 확정된 것은 411건이고
나머지는 기존 규칙 위반이다. 서울 사례에 "판정은 맞지만 대체 단지를 못 찾은" 건이 있어(길음뉴타운3단지푸르지오 →
임대동 PNU 1280-1, 진짜는 1280-0) **이번 반영은 REMATCH + 새 규칙 NO_TARGET 411건으로 한정**했다(사용자 결정).
기존 규칙 NO_TARGET 1,465건은 대체 단지 탐색 개선 후 처리한다 — 예: 화명대림타운에 붙은 코오롱하늘채1·2차는
거래 지번이 이미 실존 단지를 가리키는데 탐색이 지번 주인을 후보로 보지 않아 NO_TARGET 이 됐다.

리허설에서 드러나 함께 고친 것 (모두 기존 REMATCH 경로의 약점 또는 이번 규칙의 역효과):

1. **혼입 이름 키 이동** — `26230_동원`(고유번호 3개, 1980~1985 여러 동원)이 이름으로 당감동 동원(45세대)에
   옮겨져 ㎡당 230만→754만. REMATCH 284건 중 36건이 고유번호 2개 이상 키였다(하나·동아·동남·한국 등).
   → `rematch_bad_mappings` 에 `MIXED_KEY` 분류(옮기지도 해제하지도 않음, 사람 검토).
2. **계보 면제의 역효과** — 이름으로 고른 후보 검증에 계보 면제를 주면 옛 단지 실적이 같은 이름의 신축으로 옮겨진다.
   → `check_mapping(allow_predecessor=False)` 를 이름 기반 경로(`rematch` 이름 후보, `recalc_price` 이름 매핑)에 적용.
3. **후보 수락 기준이 약함** — `극동`(1997) 75건이 주소 후보로 주안극동스타클래스더로얄(2025)에 옮겨졌다. 이름이 겹쳐
   이름 신호가 없고 타임라인 하나라 확정 위반이 아니었다. → 대체 후보는 타임라인 신호가 하나라도 있으면 거부
   (`candidate_acceptable`). 반영분 중 17건이 이 기준으로 되돌려졌다.
4. **해제 키의 무검사 재매핑** — `recalc_price._update_mapping` 이 미매핑 이름 키를 이름으로 다시 붙이면서 물리 게이트가
   없었다. 해제 411건 중 194건이 다시 붙었다(같은 단지 0, `TRADE_` 임시 단지 188, 게이트 통과 실단지 6).
   → 이 경로에도 게이트(계보 면제 없음).

최종 로컬 반영: REMATCH 231 + 해제 411(보존 테이블 411행). 영향 단지 가격(㎡당) 변화 |%| 중앙 1.3 · 90% 11.2 ·
30% 초과 6곳 — 상위 사례를 모두 확인했다(힐스테이트 만촌역 +55%: 옛 태왕 거래 빠짐, 서면한신 +57%: 자기 이름 거래
93건 귀환, 영선동반도보라 -35%: 신축 더페로스 거래 빠짐). 대조군(월계시영고층←미륭, 관악드림타운←관악드림(삼성),
목동트라팰리스←트라팰리스이스턴에비뉴)은 유지. 처음 찾은 고신뢰 혼입 615키 중 198키가 정리됐다(해제 87,
재매핑 111 — 재매핑에는 해제 후 `TRADE_` 임시 단지로 간 키 포함). 나머지는 범위 밖 NO_TARGET·REJECTED·MIXED_KEY.

로컬 백업: `reports/trade_mix_detect/rehearsal/trade_apt_mapping_before.dump`. 로컬 반영은 다음
`sync_from_railway` 의 매핑 UPSERT 로 Railway 상태에 맞춰진다.

## 운영 반영 절차 (사용자 실행)

1. 이 변경 머지·배포 → 백엔드 부팅 시 `trade_apt_mapping_removed` 생성.
2. 리포트: `.venv/bin/python scripts/rematch_bad_mappings.py --target railway --out reports/trade_mix_detect/railway_report.json`
3. 범위 추리기: REMATCH 전부 + NO_TARGET 중 `failures` 가 {타임라인, 이름 불일치} 의 부분집합이고 이름 불일치를 포함하는 것
   (로컬과 같은 기준) → 검토본 JSON.
4. 반영: `.venv/bin/python scripts/rematch_bad_mappings.py --target railway --from-report <검토본> --apply --unmap-no-target`
5. 가격 점수는 다음 12h 거래 배치(`recalc_price`)가 재계산한다.

## 결과

- 이름 매칭 시절의 오매핑이 새 키로 조용히 넘어오지 않는다. 감사가 놓치던 "준공연도 + 이름" 동시 불일치가
  확정된다.
- 정리 후 해제된 키의 거래는 재등록 전까지 어느 단지 가격에도 반영되지 않는다 — 혼입 단지의 가격·점수는
  깨끗해지지만, 해당 단지의 거래 표본은 줄어든다(카드 후보 탈락 가능). 잘못된 단지에 붙어 있는 것보다 낫다
  (`rematch_bad_mappings` 의 기존 원칙).
- 매 배치의 상속 매핑에 물리 판정이 추가된다(신규 키 단위라 비용 작음).
- 이름 유사도 함수(`_names_overlap`)의 품질이 판정 결과에 영향을 준다 — 지금까지는 보조 지표였다.

## 기각한 대안

- **가격 분포 군집으로 혼입 탐지** — 판별력 없음(맥락 참조).
- **상속 면제 유지 + 경고 로그만** — 현행. 10/15 배치 로그에 경고가 남았지만 410키가 그대로 쌓였다.
- **이름 불일치를 단독 확정 신호로** — 같은 단지 별칭(월계시영고층 = 미륭·미성·삼호3 등, 건축년도는
  일치하는 304키)이 대량 오탐된다.
- **확정 위반을 주소 PNU 로 즉시 재매핑** — 같은 지번 다른 단지(월계주공1·2) 사례가 있어, 대체 매핑은
  반드시 판정을 통과해야 한다. `rematch_bad_mappings` 가 이미 그렇게 한다.
